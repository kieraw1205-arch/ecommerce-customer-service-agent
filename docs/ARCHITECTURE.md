# 核心架构与面试复盘

Graph 的入口是结构化意图识别。查询走受目标约束的模型工具调用/ToolNode 循环，物流/商品/确认工作流由专门节点处理；每个请求结束后由 Checkpointer 保存状态。模型漏调或改错目标时，查询适配器按已识别且验证过的目标执行确定性只读查询，不能把模型回复当成订单事实。

认证主体存于 ContextVar，线程 ID 由 user_id 与 conversation_id 哈希组成；历史读取复用同一隔离键。消息 ID 缓存只允许同 ID 同内容复用，跨内容冲突拒绝。进程内分片锁与 SQLite 支持单实例恢复，但不能据此声称支持多副本并发一致性。

催发货与退款申请先补参、查询状态，再保存等待确认状态。只有指定确认语句和目标通过校验才提交；回执先查、POST 不做自动重试。网络失败后结果未知，不能把它当失败重新生成请求标识。真实归属、唯一约束、行锁及事务必须由外部业务 API 实现，本预览只提供客户端协议与离线断言。

SSE trace/node/reply/done 由真实执行产生。Trace 分模型、工具、API、节点等 span；部分 span 嵌套，不能直接相加。模型完整返回时间可记录；TTFT 不在当前同步接口中观测。Token 只有提供方报告时才累加，缺失不等于 0。日志不记录 prompt、认证令牌或原始异常连接串。

## 三个可展示的工程案例

1. **模型与写权限分离**：Tool Calling 仅暴露只读工具；写工作流有严格确认、原请求回执和结果未知恢复。可运行工作流单测说明未确认时 POST 不发生。边界：测试使用替身，不证明外部 MySQL 事务。
2. **跨用户历史与重复消息**：认证身份控制历史键，消息 ID 防重复，内容冲突拒绝；离线 SSE 示例用两个随机令牌验证历史隔离。边界：静态 bearer 映射是演示级基础鉴权，不是完整身份平台。
3. **可复核评估而非自报成功**：工具名/参数和事实断言决定成功，错误保留在预先声明的分母；输入不给答案，评分器保留失败明细。边界：公开过的留出集不再是盲测，mock 测试不算模型准确率。
